Across the five captured generation rounds, answering time correlates with
output tokens at 0.770 and input tokens at 0.811. This tiny sample does not
establish which factor dominates latency. Do not justify a model or context

## Ranked observed failures

1. **Listing pages establish hotel facts.** Hotel run
   `86d6df57-1a56-4365-9b28-8b122f8d47d0` displays nine facts backed only by
   city/theme/search listings. For example, Booking's `/budget/city/ee/parnu.html`
   says “most popular cheap hotels in pärnu” and is used as destination evidence.
   Stage: grounding/source acceptance. Maps to Q2 and optimization R2.2.
2. **Wrong accommodation type passes.** The same run marks the Narva hotel
   requirement met for Transhostel Romantika. The captured theme listing calls
   it an “apartment”. Stage: type grounding. Maps to Q6/R2.2.
3. **A nearby town's passage becomes Narva budget evidence.** The sentence lists
   spa hotels in “narva jõesuu” among several towns; it does not establish a
   Narva destination budget. Stage: entity alignment. Maps to Q4/R2.2.
4. **A museum name establishes an island relationship.** Hotel Mardi's Trivago
   passage establishes its address and Kuressaare distance. “Saaremaa Museum”
   does not establish every geographic assertion added to the statement.
   Stage: statement alignment. Maps to Q4/R2.2.
5. **Stock is absent for every laptop.** Laptop run
   `f06b2f93-a358-4acc-b5b4-70805d661e0b` has three unknown stock checks even
   after refinement. The captured Gigantti pages expose prices and specifications
   without explicit stock text. Stage: retrieval/gap priority. Maps to Q5/R2.2.
6. **Delivery never gains seller policy evidence.** All three laptop delivery
   checks remain unknown. Verifier rejection: “Gigantti URL does not prove local
   stock or delivery to Finland.” Stage: policy retrieval/reuse. Maps to Q5/R2.4.
7. **One retailer and an unlabeled outlet offer.** All laptop candidates are from
   Gigantti; the HP 15-fc0851no source is `/product/outlet/.../969385`, priced
   at `559,00 €`. Stage: selection/display. Maps to Q5/R2.1/R2.2.
8. **Ten placeholder rows obscure the remaining facts.** The hotel table has four
   “Not found” cells and the laptop answer has six placeholder lines.
   Stage: rendering. Maps to Q8/R2.1.
9. **The failed Tartu hostel persists.** The hotel run stops at
   `no_evidence_progress` with Hektor Design Hostel still the named Tartu stay.
   Its own page explicitly says “Hektor Design Hostel”. Stage: replacement and
   stopping. Maps to Q7/R2.2.
10. **Queue time confounds latency comparisons.** The old three-thread evaluator
    reports a 20.19-second observed queue for the laptop run while the supervisor
    handles two runs at once. The new protocol caps concurrency at two and keeps
    queue and worker time separate. Stage: evaluation. Maps to Q10.

## Implementation and regression checks

Q1–Q9 are implemented in the answer pipeline: scoped and atomic requirements,
source classification at retrieval and grounding, structured knowledge answers,
compact value/passage output, local statement alignment, retailer diversity and
condition labels, price/VAT guards, compound accommodation types, prioritized
replacements, consolidated confirmation notes, and persistent caches with
original observation dates. Business lookups render field tables. Cached opening
hours cannot remain confirmed, and related-product passages cannot borrow the
main page's identity.

Q10 supplies the ten-case live protocol, independent scorer, partial historical
gold, and captured-page regressions. The populated regression fixture includes
provenance hashes and excerpts from the actual pages behind F1–F11. The code
does not treat the seven unaudited cases as passing.

The pre-change full backend baseline passed 515 tests. After implementation,
the backend tests that do not use FastAPI's TestClient pass (557 tests). The
full `uv run --no-sync pytest` check was attempted with a writable uv cache and
a 15-second bound. It timed out in TestClient's AnyIO portal startup, before
executing the API fixture. A five-second traceback identifies the portal wait;
this is recorded as an environment-blocked check, not a passing full suite.
The compact output validator runs directly in the model event loop, avoiding a
thread hop for local evidence processing.

The saved-answer re-grounding comparison was repeated after the final source
and alignment fixes. Precision does not fall on the audited retained claims;
SEO-only facts and unsupplied citations remain zero. Laptop fixed-candidate
recall remains 7/11. Refinement now explicitly searches retailers other than
the already retained sellers, but its ability to recover the missing candidate
still requires the blocked live retrieval protocol.
